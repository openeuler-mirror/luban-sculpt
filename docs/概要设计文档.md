## 1. 引言

### 1.1 编写目的

描述 **Luban-Sculpt** 的定位、正交设计轴、模块边界与端到端主路径，作为详细设计与实现对照的概要基线。本文侧重 **WHY / 结构**；字段与协议见《详细设计文档》。

### 1.2 项目背景

国产化 LLM 推理需同时适配 **多芯片**（Ascend、海光 DCU、NVIDIA）与 **多模型结构**（Dense / MoE / 多模态）。单一量化工具链无法统一硬件差异与架构策略，因此需要一套 **编排框架**：硬件感知 → 架构分类 → Recipe 编译 → 多 Backend 执行 → 产物校验与部署提示。

### 1.3 术语

| 术语 | 含义 |
|------|------|
| **HAE** | Hardware-Aware Engine：探测硬件并生成 `HwDecision` |
| **HAL** | Hardware Abstraction Layer：校准 kernel 选择 / encoding / layout（当前多为 stub） |
| **ModelArch** | 模型架构分类（llama / qwen / deepseek_moe …） |
| **ArchQuantPolicy** | 架构量化策略（ignore、偏好算法、MoE 校准提示） |
| **Recipe** | 量化配方 YAML（`model_id` / `quant` 或 `pipeline` / `calib`） |
| **Profile** | 芯片能力模板 YAML（`profiles/*.yaml`） |
| **BackendPlan** | 单阶段执行契约：`QuantIntent` + `HwDecision` + `ExportFormat` |
| **CalibRunner** | 全 Backend 共用的校准数据入口 |
| **Dry-Run** | 缺工具时写可复现脚本/stub，仍产出 `manifest.json` |
| **PTQ** | Post-Training Quantization |

### 1.4 设计原则

1. **两条正交轴**：硬件（HAE + Profile）与模型架构（ModelArch）独立演进。  
2. **Backend 只做算法适配**：不做架构分类、不做硬件探测。  
3. **Fail-Fast**：能力门禁（`QuantCapabilityError`）不匹配即失败，不静默降级（HAE probe 可配置 degraded）。  
4. **Dry-Run 优先**：无国产卡 / 无量化工具时仍可全链路空转联调。  
5. **可扩展**：新芯片加 Profile；新架构加 ModelArch 策略；新引擎加 Backend entry-point；新阶段实现 `PipelineStage`。

## 2. 系统概述

### 2.1 定位

Luban-Sculpt 是硬件感知的多后端 **PTQ 编排 CLI/SDK**。编排入口为 `luban_sculpt.pipeline.QuantPipeline`（CLI `compress` 亦走此路径）。产物经 HAL 写 `manifest.json`，供 vLLM / vLLM-Ascend / vLLM-ROCm 等加载。

### 2.2 目标硬件与软件栈

| 厂商 | 硬件 | 主 Backend（代码现状） | 运行时 |
|------|------|------------------------|--------|
| 华为 | Ascend 910B 等 | `msmodelslim`（CLI） | vLLM-Ascend |
| 海光 | DCU | `awq` / `gptq`（awq 多为 stub；gptq 可接 GPTQModel） | vLLM-ROCm |
| NVIDIA | H20 / CUDA | `llm_compressor` / `gptq` | vLLM |
| 通用 | CPU / CI | `generic_cpu` Profile + Dry-Run | — |

> 说明：文档/示例中的「lmslim」为海光厂商工具链方向；**当前 `pyproject` 未注册 `lmslim` entry**，海光 recipe 走 `awq`/`gptq`。

### 2.3 量化方案（Recipe `abstract_scheme` 示例）

| Scheme | 典型 Profile | Backend |
|--------|--------------|---------|
| `fp8_dynamic` / `fp8_block` | `nvidia_h20` | `llm_compressor` |
| `w4_gptq` | `nvidia_h20` | `gptq` |
| `ascend_w8a8` / `ascend_w4a8` / `ascend_fp8` | `ascend_910b` | `msmodelslim` |
| `hygon_w4a16_awq` | `hygon_dcu` | `awq` |
| `hygon_w8a8_gptq` | `hygon_dcu` | `gptq` |

### 2.4 非目标（当前版本）

- 不替代各厂商量化工具内部算法实现  
- 不实现完整训练态 QAT  
- HAL 真实 fused kernel / NZ 布局变换（接口已留，实现多为 stub）  
- 多阶段间真实权重图变换（目录级串联已具备，算法级 handoff 仍偏骨架）

## 3. 总体架构

### 3.1 正交轴

```
                 ModelArch（模型）
                    │
     dense / moe / VL 策略、ignore、calib 放大
                    │
HAE Profile ────────┼──────── BackendPlan ──► Backend
（芯片 / 编码 / 布局）│
                    │
                 HwDecision
```

| 轴 | 模块 | 回答 | 禁止做 |
|----|------|------|--------|
| 硬件 | `hae/` + `profiles/` | 哪块卡、编码、布局、拓扑 | 跳哪些层、MoE 策略 |
| 模型 | `model/` | 架构、ignore、偏好算法 | SoC、CANN/DTK |
| 编配 | `pipeline/` | 多 backend×algorithm 顺序与输入来源 | 替代 Backend 内部算法 |
| 校准 | `calib/` | 统一样本加载与 sidecar | 厂商特定校准算子 |
| 执行 | `backends/` | 消费本阶段 `BackendPlan` | 再探测硬件 / 再分类架构 |
| 门禁 | `validate/` | 压前能力检查 / 压后产物检查 | 修改权重 |

### 3.2 逻辑分层

```
CLI / SDK
    │
    ▼
QuantPipeline
    ├─ HAEStage                 → HwDecision, ProbeResult
    ├─ BackendComposeStage      → 每阶段：compile → Gate → Backend → HAL/manifest
    └─ QuantizedModelValidateStage（可选）→ HF config / runtime
    │
    ▼
export: manifest.json (+ pipeline_manifest.json / sidecars)
```

### 3.3 层间中枢

单阶段执行只认 **`BackendPlan`**：

- **QuantIntent**：model、backend、scheme、ignore、calib、`backend_options`、`arch_snapshot`  
- **HwDecision**：profile、融合/编码/布局/拓扑、probe 结果  
- **ExportFormat**：产物加载协议（compressed-tensors / gptq_hf / vllm_ascend …）

## 4. 模块划分

| 包路径 | 职责 |
|--------|------|
| `contracts/` | IR / DTO（Pydantic） |
| `pipeline/` | `QuantPipeline`、阶段、`parse_pipeline_config` / `build_stage_recipe` |
| `compiler/` | Recipe → `BackendPlan`（含 ModelArch 合并） |
| `hae/` | 硬件探测、Profile 解析、算子 probe、合成 `HwDecision` |
| `hal/` | 校准 kernel 名 / encoding / layout / repack（stub 为主） |
| `model/` | `resolve_model_arch`、dense/moe 策略与 patterns |
| `calib/` | `CalibRunner`、`iter_text_samples`（stub / HF） |
| `backends/` | entry-point 插件：`llm_compressor` / `msmodelslim` / `gptq` / `awq` / `custom` |
| `validate/` | `quant_capability`（压前）+ `quantized_model` / `hf_config` / `runtime`（压后） |
| `export/` | `build_manifest`、layout 标记 |
| `log/` | 统一日志 |
| `profiles/` / `recipes/` | 打包内置 YAML |
| `cli.py` | `luban-sculpt` 入口 |

测试目录 **`tests/`** 与上述模块对齐（见 `tests/README.md`）。

## 5. 端到端流程

### 5.1 compress（主路径）

```
luban-sculpt compress --recipe R --profile P --output O
        │
        ▼
QuantPipeline.run
  1. load_recipe_yaml + parse_pipeline_config
  2. HAEStage：HardwareAwareEngine.run → HwDecision / ProbeResult
  3. BackendComposeStage（每个 enabled stage）：
       build_stage_recipe → compile_recipe → BackendPlan
       validate_quant_capability
       BackendRouter → QuantBackend.quantize
         CalibRunner（各 runner 自行接入）
         run_with_hal → HAL + manifest.json
       写 pipeline_stage.json
     写 pipeline_manifest.json
  4. [可选] QuantizedModelValidateStage → quantized_model_validate.json
  5. 返回最后一阶段 QuantizedArtifact
```

### 5.2 其它 CLI

| 命令 | 作用 |
|------|------|
| `probe` | 仅跑 HAE，打印 JSON |
| `validate` | 对已有产物目录做 HF config（+ 可选 runtime）校验 |
| `report` | 打印 `manifest.json` |
| `backends` / `ascend-chips` / `model-arches` | 枚举注册表与策略表 |

### 5.3 Recipe 形态

- **单阶段（兼容）**：顶层 `quant:` → 自动变成一个 `QuantStageConfig`  
- **多阶段**：`pipeline.stages[]`，支持 `input_from: previous`、`output_subdir`、`algorithm`

校准统一写在顶层 `calib:`（经编译进入 `QuantIntent.calib`，由 `CalibRunner` 消费）。

## 6. 扩展点

| 扩展 | 做法 |
|------|------|
| 新芯片 | 新增 `profiles/<id>.yaml`，必要时扩展 HAE 探测 |
| 新模型架构 | `model/dense` 或 `model/moe` 策略 + patterns |
| 新 Backend | 实现 `QuantBackend`，在 `pyproject.toml` 注册 `luban_sculpt.backends` entry |
| 新流水线阶段 | 实现 `PipelineStage.run(ctx)`，`QuantPipeline(stages=[...])` |
| 校准源 | `calib.source`：`stub` / HF dataset id；msmodelslim 可物化 `luban_calib.jsonl` |

## 7. 风险与已知差距

| 风险 / 差距 | 说明 | 缓解 |
|-------------|------|------|
| HAL stub | encoding/layout/calib_forward 未接真 kernel | Dry-Run + manifest 对账；后续 HAL 实装 |
| awq / custom stub | 无真实量化工具调用 | 海光路径优先 gptq；awq 待接厂商 SDK |
| 多阶段 handoff | 以目录 `model_id` 串联为主 | Recipe 注释标明骨架；后续补权重协议 |
| HAE probe 代理 | `probe_ops` 多为 matmul 延迟/MSE，非厂商 fused 算子 | Profile `required_ops_probe` + degraded 策略 |
| 可选依赖体积 | vllm / llmcompressor / gptqmodel 大 | `requirements.txt` 中可注释；或按 extras 安装 |
| Ascend 工具链 | msModelSlim 非 PyPI 统一包 | 官方 install.sh + PATH / Dry-Run |

排期与里程碑细节见 `docs/schedule_2026.md`（若与本文冲突，**以代码与本文/详细设计为准**）。
